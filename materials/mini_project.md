# Mini-project: Data analysis (командный)

> Источник: [academy-avu.pages.dev/projects](https://academy-avu.pages.dev/projects). Ваша команда — Mars, трек C (MerchantHub), решение в [`uzcard-merchanthub/`](../uzcard-merchanthub/).

Групповая работа (2–3 человека). Защита: 07.07, 09.07, 10.07, 14.07.2026 (занятия 24–27). Выступление команды — 5 минут.

Команда получает бизнес-задачу от условного заказчика и проводит аналитическое исследование. Готовых вопросов, перечня таблиц и схемы связей не выдаётся.

## Данные

- Синтетические финтех-данные (платежи, клиенты, мерчанты, приложение, доставка) в схеме `public` базы `academy_db`.
- Все таблицы с префиксом `ds_`. В базе перемешано несколько предметных областей (по числу треков); какая таблица к какому треку — не указано.
- Одинаковые типы из разных областей разведены суффиксом: `ds_transactions_1/_2`, `ds_merchants_1..3`, `ds_terminals_1/2`, `ds_users_1/2`. Своя определяется по колонкам.
- Таблицы соединяются по общим ключам (`*_id`). Проверяйте связь через JOIN, а не по совпадению названий.

```sql
-- список всех учебных таблиц
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public' AND table_name ~ '^ds_';

-- колонки конкретной таблицы
SELECT column_name, data_type FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'ds_...';

-- примеры строк и уникальные значения
SELECT * FROM public.ds_... LIMIT 10;
SELECT DISTINCT нужная_колонка FROM public.ds_...;
```

## Порядок работы

1. Разобрать данные: найти таблицы своего трека среди `ds_*` и установить связи.
2. Сформулировать гипотезы в рамках бизнес-задачи.
3. Проверить каждую гипотезу данными (SQL и Python), получить числовой результат.
4. Сформулировать практическую рекомендацию.
5. Представить результаты на защите.

## Требования

- Каждый участник ведёт и защищает минимум одну собственную гипотезу; гипотезы не дублируются.
- Решение требует JOIN нескольких таблиц.
- Обязательный минимум на команду: JOIN, GROUP BY, подзапрос или CTE, оконная функция. Не менее двух графиков на гипотезу.
- ML-модели не допускаются: SQL, pandas, визуализация, описательная и проверочная статистика, правила.
- Каждый вывод подтверждается числом.
- Минимум одна находка команды подкреплена статметодом (тест значимости, доверительный интервал или метрика концентрации). Для трека D — обязательно для каждого; для A/B/C — минимум одна на команду и дополнительный балл.

## Результаты работы

- **Notebook.** Разделы по гипотезам, подписанные именем автора: запрос, график, вывод.
- **Презентация.** 5–7 слайдов по схеме problem-solution. Один слайд — одна мысль; на каждой находке график и ключевое число.
- **Выступление.** Не более 4 минут на команду + 1 минута на вопросы. Превышение — доклад прерывается. Каждый представляет свою часть.
