# Задание: Отток клиентов — определить, измерить, предсказать

Источник: `lessons/week_churn_model.ipynb` / `notebooks/week_churn_model.ipynb`

## Контекст

Бизнес: «Мы теряем клиентов. Нужна модель, которая покажет, кто уйдёт следующим».

В скоринге таргет выводился из платежей. Здесь события «ушёл» нет: клиент просто перестаёт пользоваться картой. Отток определяете вы сами.

## Данные

- PostgreSQL, схема `public`, таблицы `churn_*`
- Дата среза выгрузки: **2025-12-31**
- Не все `churn_*` таблицы пригодны — нужно обосновать отбор

## Шаги

1. **Определить отток** — порог тишины (дней без операций), snapshot-дата, горизонт предсказания. Обосновать через распределение пауз между операциями.
2. **Собрать базу** — кого включать / исключать: уже молчащие, новички без истории, незакрытое окно наблюдения.
3. **Понять динамику** — отток по месяцам, когда вырос, что в данных это объясняет, все ли сегменты пострадали одинаково.
4. **Фичи** — строго до snapshot; уровень и динамика активности; приложение, поддержка, продукты; не перепутать сезонность с уходом.
5. **Модель** — обучение на одном срезе, проверка на следующем (out-of-time); важность фичей; бизнес-метрики.
6. **Ответ бизнесу** — кого удерживать при ограниченном бюджете, где модель окупается.

## Защита (две части в одной презентации)

**Часть 1. Таргет.** Определение, порог, snapshot, горизонт, исключения, доля оттока, динамика и причина роста.

**Часть 2. ML-модель.** Фичи, out-of-time валидация, метрики для бизнеса, топ риска и тактика удержания.
