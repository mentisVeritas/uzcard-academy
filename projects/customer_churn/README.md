# Customer Churn — Отток клиентов

Домашнее задание 5: определить отток, измерить его и построить модель, которая покажет, кто уйдёт следующим.

## Контекст

Директор по продуктам: «Мы теряем клиентов. Нужна модель, которая покажет, кто уйдёт следующим».

В отличие от скоринга, готового события «ушёл» в базе нет: клиент не расторгает договор, а просто перестаёт пользоваться картой. Таргет нужно определить самим.

## Данные

- PostgreSQL `academy_db`, схема `public`, таблицы `churn_*`
- Срез выгрузки: **2025-12-31**
- В выгрузке есть мусор и подозрительные витрины — отбор таблиц часть задания

## Быстрый старт

```bash
cd projects/customer_churn
uv sync                          # создаёт .venv
source .venv/bin/activate        # или: uv run jupyter notebook …
jupyter notebook notebooks/churn.ipynb
```

Ядро Jupyter: **customer_churn** (ставится `uv run python -m ipykernel install --user --name customer-churn --display-name customer_churn`).

Каркас задания (официальный стартер): `notebooks/week_churn_model.ipynb`.  
Рабочий разбор таргета и графики для слайдов: `notebooks/churn.ipynb` — картинки пишутся в `presentation/assets/`.

## Что сдать

1. **Таргет** — определение оттока, snapshot, горизонт, кого исключили, доля и динамика
2. **ML-модель** — фичи до snapshot, out-of-time проверка, метрики, кого удерживать при ограниченном бюджете
3. Ноутбук + презентация
