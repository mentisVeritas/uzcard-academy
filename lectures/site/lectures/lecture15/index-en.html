Joining

merge joins two tables by a key

Data is spread across tables: transactions have card_id but not the client segment. merge pulls columns from the second table by a common key. This is the analog of SQL JOIN, which comes in Lecture 15.

transactions

Transactions

  • card_id, amount, region
cards

Cards reference

  • card_id, segment
  • join key: card_id

Join types

inner, left, right, outer

A key may not appear in all tables. The join type decides which rows end up in the result.

inner

Only common keys, present in both tables.

left

All rows of the left table, no match -> NaN.

right

All rows of the right table.

outer

All keys from both tables.

Most often you need left: keep all of your own data and pull in reference data without losing anything.

Question

After a left merge the table grew from 10,000 to 12,000 rows. How is that possible with a left join?

A left join should keep all rows of the left table and not add new ones. But the row count increased.

Answer

Many-to-many: one card_id appeared in the right table several times

merge duplicates the transaction row for each pair. If one card_id repeats in cards, every transaction with that id gets multiplied. Solution: cards.drop_duplicates("card_id") before merge.

Question

In the region column, 300 rows have NaN. How many of them will be included in groupby("region").sum()?

The data is real: some transactions arrived without a region. groupby is called without extra parameters.

Answer

None: groupby silently drops NaN keys

By default groupby discards rows where the key column is NaN (dropna=True). The 300 transactions without a region will not enter any group. To get a NaN group: df.groupby("region", dropna=False).sum().

Pivot tables

pivot_table: aggregate across two dimensions

groupby reduces by one key. pivot_table lays the aggregate out across two: one dimension in the rows, another in the columns. For example, turnover by region (rows) and category (columns) in a single table.

Time

A date is a separate data type

to_datetime turns a string into a date. After that the .dt accessor gives the hour, day, month, and resample groups rows by time intervals (by hours, by days) and computes an aggregate inside each. More on time series in later lectures.
