История

pandas создан в 2008 году для анализа финансовых данных

Уэс Маккини написал pandas, работая в инвестиционном фонде. Python умел считать числа, но не имел удобного инструмента для таблиц. Сегодня pandas установлен почти на каждой машине, где работают с данными.

Определение

pandas это программируемая таблица

Таблица с именами столбцов, метками строк, разными типами данных в одной структуре и большим набором операций над ними. То, что в Excel делают мышкой, здесь делают кодом и сразу на миллионах строк.

Строка это запись (одна транзакция). Столбец это признак (сумма, регион, мерчант). Ячейка это одно значение.

Зачем это

Сто миллионов транзакций в месяц лежат в таблицах, а не в массивах

UZCARD обрабатывает около 100 млн операций в месяц. У каждой есть сумма, регион, мерчант, время и статус. NumPy-массив хранит числа одного типа и не помнит имён столбцов. pandas хранит именно таблицу.

NumPy-массив

Только числа

  • Один тип данных на весь массив
  • Нет имён столбцов
  • Регион и сумма не лежат рядом
pandas DataFrame

Таблица

  • Столбцы разных типов: число, текст, дата
  • У каждого столбца есть имя
  • Строка = одна транзакция целиком

Экосистема

pandas стоит поверх NumPy

Внутри каждый столбец pandas хранится как NumPy-массив. NumPy даёт скорость, pandas добавляет сверху имена столбцов, индекс строк и разные типы в одной таблице.

pandas - таблицы: имена столбцов, индекс, разные типы
NumPy - массивы: векторизация, скорость
C и память - быстрые циклы под капотом

Три объекта

NumPy массив, Series, DataFrame

Каждый следующий объект строится на предыдущем.

NumPy массив

Числа одного типа, без подписей. Чистая скорость.

Series

Одномерный массив плюс индекс (метки строк). Один столбец.

DataFrame

Таблица: набор столбцов Series с общим индексом. Основной объект.

Series: столбец с подписанными строками

Series это одномерный массив NumPy плюс индекс (метки строк). У него есть имя, тип и те же векторные операции, что в Лекции 11.

DataFrame

DataFrame: набор столбцов с общим индексом

DataFrame это таблица. Каждый столбец это Series, все одной длины и с общим индексом строк. Доступ к одному столбцу возвращает Series.

Строки это транзакции, столбцы это признаки. Таблица, столбец и ячейка это три уровня одного объекта.

Пример

Таблица в коде

df = pd.DataFrame({ "merchant": ["Korzinka", "Evos", "Texnomart"], "amount": [125000, 45000, 2300000], "region": ["Ташкент", "Самарканд", "Ташкент"], }) print(df.shape) # (3, 3): строки, столбцы

Словарь столбцов превращается в таблицу. Каждый ключ это имя столбца, каждый список это его значения.

Под капотом

Каждый столбец это отдельный типизированный массив

DataFrame хранит столбцы как отдельные типизированные массивы NumPy. Поэтому операция над столбцом идёт со скоростью NumPy, а в разных столбцах могут быть разные типы.

print(df.dtypes) # merchant object (текст) # amount int64 (число) # region object (текст)

Когда что

NumPy, Series или DataFrame

NumPy

Чистые числа, матрицы, линейная алгебра, максимум скорости.

Series

Один подписанный столбец, быстрый поиск по метке, один признак.

DataFrame

Таблица со смешанными типами, любой реальный анализ данных.

В большинстве реальных задач работают с DataFrame. Series получают, когда берут один столбец. NumPy считает математику под капотом.

Типы данных

У каждого столбца один тип

Тип столбца решает три вещи: сколько памяти он занимает, как быстро идут операции и какие действия возможны. pandas выбирает тип сам при чтении файла, но часто его приходится исправлять.

Число, текст и дата это разные типы. Сложить можно числа, привести к верхнему регистру можно текст, вычесть одну дату из другой можно даты.

NumPy

Числовые типы: один размер - один блок памяти

Скорость NumPy держится на одном принципе: все значения одного типа занимают ровно одинаковое число байт и лежат в памяти сплошным непрерывным блоком. Процессор знает, где следующее значение, и шагает по блоку без участия Python.

int8 / 16 / 32 / 64

Целые числа. 1, 2, 4 или 8 байт на значение. Диапазон зависит от размера.

float32 / float64

Числа с дробной частью. 4 или 8 байт. float64 это стандарт в науке о данных.

bool

True или False. 1 байт. Основа булевых масок из Лекции 11.

С текстом этот принцип ломается: строки бывают разной длины. NumPy решает задачу тремя способами - и у каждого своя цена.

NumPy: текст

Три способа хранить текст в NumPy

Каждый подход решает проблему длины по-своему. Выбор влияет на память, скорость и то, какие языки вообще можно хранить.

U - Unicode

Фиксированная ширина. 4 байта на символ. Любой язык, включая русский. Слишком длинная строка молча обрезается.

S - байты

Фиксированная ширина. 1 байт на символ. Только латиница. В 4 раза экономнее U, но кириллица вызывает ошибку.

object

Не само значение, а адрес (указатель) на строку в памяти. Гибко, но медленно: векторизация не работает.

U в действии

U: фиксированная ширина и молчаливое обрезание

>>> a = np.array(["Korzinka", "Evos", "Texnomart"]) >>> a.dtype dtype('<U9') # ширина = самая длинная (9) >>> a[0] = "Texnomart Plaza" # 15 символов >>> a array(['Texnomart', 'Evos', 'Texnomart'], dtype='<U9') # ↑ обрезано до 9 — молча, без ошибки

a[0] = "Texnomart Plaza"

Texnomart✂·Plaza

Ячейка вмещает ровно 9 символов. Лишнее отброшено без ошибки — данные теряются тихо.

S в действии

S: один байт на символ — и падение на кириллице

>>> b = np.array(["Tashkent", "Evos"], dtype="S") >>> b array([b'Tashkent', b'Evos'], dtype='|S8') # 1 байт/символ >>> np.array(["Ташкент"], dtype="S") UnicodeEncodeError: 'ascii' codec can't encode characters in position 0-6
"Tashkent"→b'Tashkent'✓

латиница: каждый символ — 1 байт ASCII

"Ташкент"→✗ UnicodeEncodeError

кириллица не помещается в ASCII

object в действии

object: 8 байт указателя вместо строки

>>> o = np.array(["Ташкент", "Самарканд"], dtype=object) >>> o.dtype dtype('O') >>> o.itemsize 8 # 8 байт = указатель, не строка

массив object: указатели подряд

0x··a10x··c80x··04
↓↓↓

строки разбросаны по куче

"Самарканд" "Ташкент" "Бухара"

Массив указателей занимает мало (50 000 регионов — всего 0.4 МБ), но сами строки лежат отдельными Python-объектами. Процессор прыгает за каждым: cache miss на каждом элементе, векторизация не работает.

NumPy

Текстовые типы: U и S

В NumPy текст это тип фиксированной ширины: ширина равна самой длинной строке, и слишком длинное значение молча обрезается.

S - байты

1 байт на символ

  • Только латиница (ASCII)
  • На кириллице падает с ошибкой
  • Экономит память
U - Unicode

4 байта на символ

  • Любой язык, включая русский
  • Занимает больше памяти
  • Выбор по умолчанию для текста

Под капотом

object: массив указателей, не значений

Тип object хранит не сами строки, а 64-битные адреса: указатели на места в оперативной памяти, где строки реально лежат. Сами строки при этом разбросаны по памяти как попало.

object - указатели

Cache miss на каждом элементе

  • CPU читает адрес
  • Прыгает в другую часть памяти
  • Читает строку
  • Возвращается за следующим адресом
int64 - значения

Процессор шагает по блоку

  • Все значения лежат рядом
  • Следующее = +8 байт
  • Кэш процессора не сбрасывается
  • Векторизация работает

В pandas 3.0 чистый текстовый столбец по умолчанию получает тип str, а не object - это первый шаг к возврату скорости.

Умные типы pandas

Extension types: пропуски и экономия

pandas добавил расширенные типы поверх NumPy. Они хранят пропуски прямо в столбце и экономят память.

string

Отдельный тип для текстовых столбцов. Поддерживает NA. Не допускает смешивания с числами или списками.

Int64, boolean

Целые числа и логический тип с поддержкой NA. Заглавная буква отличает их от NumPy-аналогов.

category

Уникальные значения хранятся один раз. В столбце стоят числовые коды. Экономит память в 10-100 раз.

datetime (TZ)

Момент времени с часовым поясом.

Period

Отрезок календаря: квартал, месяц.

Interval

Числовой диапазон, например (0, 10].

Пропуски в целых

Int64: целое с пропуском

Обычное целое NumPy не хранит NaN, поэтому один пропуск превращает столбец в дроби и портит числовые id.

обычный int + NaN

Уходит в float

  • 101 становится 101.0
  • числовой id испорчен
Int64

Остаётся целым

  • 101 остаётся 101
  • пропуск это <NA>

Память

category: числовые коды вместо строк

Когда в столбце мало разных значений, повторяющихся много раз (города, статусы), тип category хранит каждую строку один раз в словаре, а в столбце держит маленькие коды. На столбце из тысяч повторов это уменьшает память в десятки раз.

Измерить память столбца: memory_usage(deep=True). Параметр deep обязателен для текста, иначе считается только размер ссылок.

Вопрос

Столбец status имеет тип string. df[df["status"].str.contains("success")] падает с ошибкой. Тот же код работал, когда тип был object. Почему?

str.contains() отработал без ошибки и вернул результат. Ошибка возникла при использовании результата как маски для индексации.

Ответ

string возвращает NA вместо False на пустых ячейках - маска с NA не работает

С типом object пустая ячейка даёт False в str.contains(). С типом string - NA. pandas не может использовать маску с NA для индексации. Решение: df["status"].str.contains("success", na=False) - параметр na=False заменяет NA на False.

Очистка

Очистка занимает 60-70% времени проекта

Реальные данные приходят грязными: пропуски, числа как текст, дубликаты, разный регистр в категориях. Очистка идёт до анализа, потому что плохие данные на входе дают неверные выводы на выходе.

Анализ на неочищенных данных даёт неверные результаты. Очистка идёт до любых расчётов.

Фильтрация

Булева маска отбирает строки по условию

Сравнение столбца с числом даёт массив True/False по каждой строке. В квадратных скобках он оставляет только строки, где True. Это продолжение булевых масок из Лекции 11.

Несколько условий объединяют через & (И) и | (ИЛИ), каждое в круглых скобках. Слова and и or здесь не работают.

Вопрос аудитории

Ты написал filtered = df[df.amount > 1e6], потом filtered["fee"] = 0. Изменился ли оригинальный df?

Интуитивно кажется что да, filtered это та же таблица. Но Python показывает SettingWithCopyWarning.

Ответ

df не изменился: фильтрация вернула копию

Фильтрация может вернуть копию или вид - непредсказуемо. Запись идёт в копию, оригинал не меняется. Правильно: df.loc[df.amount > 1e6, "fee"] = 0 - один вызов loc гарантирует запись в оригинал.

Пропуски

NaN: отсутствующее значение

В реальных данных часть значений отсутствует и помечается как NaN. NaN не равен ничему, даже самому себе, поэтому сравнением == его не поймать. Агрегаты вроде mean пропускают NaN автоматически.

Пропуски находят через isna, удаляют через dropna или заполняют через fillna. Что выбрать, зависит от того, можно ли терять строку.
