pandas

Series · DataFrame · data types · loading · cleaning

History

pandas was created in 2008 to analyze financial data

Wes McKinney wrote pandas while working at an investment fund. Python could crunch numbers but had no convenient tool for tables. Today pandas is installed on almost every machine that works with data.

Definition

pandas is a programmable table

A table with column names, row labels, different data types in one structure and a large set of operations over them. What people do with a mouse in Excel, here is done with code and right away on millions of rows.

A row is a record (one transaction). A column is a feature (amount, region, merchant). A cell is one value.

Why this matters

A hundred million transactions a month live in tables, not in arrays

UZCARD processes about 100 million operations per month. Each one has an amount, region, merchant, time and status. A NumPy array stores numbers of one type and does not remember column names. pandas stores exactly the table.

NumPy array

Numbers only

  • One data type for the whole array
  • No column names
  • Region and amount do not sit together
pandas DataFrame

Table

  • Columns of different types: number, text, date
  • Every column has a name
  • A row = one whole transaction

Ecosystem

pandas sits on top of NumPy

Internally each pandas column is stored as a NumPy array. NumPy gives speed, pandas adds column names, a row index and different types in one table on top of it.

pandas - tables: column names, index, different types
NumPy - arrays: vectorization, speed
C and memory - fast loops under the hood

Numbers of one type, without labels. Pure speed.

A one-dimensional array plus an index (row labels). One column.

A table: a set of Series columns with a shared index. The main object.

Series

Series: a column with labeled rows

A Series is a one-dimensional NumPy array plus an index (row labels). It has a name, a type and the same vector operations as in Lecture 11.

One column of a table is a Series. Its values are a NumPy array, and the index sets the row labels.

df["amount"]

0125 000
1 45 000
22 300 000

Name: amount, dtype: int64

DataFrame

DataFrame: a set of columns with a shared index

A DataFrame is a table. Each column is a Series, all of the same length and with a shared row index. Accessing one column returns a Series.

Rows are transactions, columns are features. Table, column and cell are three levels of one object.

Example

A table in code

df = pd.DataFrame({ "merchant": ["Korzinka", "Evos", "Texnomart"], "amount": [125000, 45000, 2300000], "region": ["Tashkent", "Samarkand", "Tashkent"], }) print(df.shape) # (3, 3): rows, columns

A dictionary of columns turns into a table. Each key is a column name, each list is its values.

Under the hood

Each column is a separate typed array

A DataFrame stores columns as separate typed NumPy arrays. That is why an operation over a column runs at NumPy speed, and different columns can hold different types.

print(df.dtypes) # merchant object (text) # amount int64 (number) # region object (text)

When to use what

NumPy, Series or DataFrame

NumPy

Pure numbers, matrices, linear algebra, maximum speed.

Series

One labeled column, fast lookup by label, one feature.

DataFrame

A table with mixed types, any real data analysis.

In most real tasks you work with a DataFrame. You get a Series when you take one column. NumPy does the math under the hood.

Data types

Each column has one type

A column's type decides three things: how much memory it takes, how fast operations run and what actions are possible. pandas picks the type itself when reading a file, but you often have to fix it.

Number, text and date are different types. You can add numbers, uppercase text, and subtract one date from another.

NumPy

Numeric types: one size - one memory block

NumPy's speed rests on one principle: all values of the same type occupy exactly the same number of bytes and sit in memory as one solid contiguous block. The processor knows where the next value is and steps through the block without involving Python.

int8 / 16 / 32 / 64

Integers. 1, 2, 4 or 8 bytes per value. The range depends on the size.

float32 / float64

Numbers with a fractional part. 4 or 8 bytes. float64 is the standard in data science.

bool

True or False. 1 byte. The foundation of the boolean masks from Lecture 11.

With text this principle breaks down: strings can be of different lengths. NumPy solves the problem in three ways - and each has its own cost.

NumPy: text

Three ways to store text in NumPy

Each approach solves the length problem in its own way. The choice affects memory, speed and which languages can be stored at all.

U - Unicode

Fixed width. 4 bytes per character. Any language, including Russian. A string that is too long is silently truncated.

S - bytes

Fixed width. 1 byte per character. Latin only. 4 times more memory-efficient than U, but Cyrillic causes an error.

object

Not the value itself but an address (pointer) to a string in memory. Flexible but slow: vectorization does not work.

U in action

U: fixed width and silent truncation

>>> a = np.array(["Korzinka", "Evos", "Texnomart"]) >>> a.dtype dtype('<U9') # width = longest string (9) >>> a[0] = "Texnomart Plaza" # 15 characters >>> a array(['Texnomart', 'Evos', 'Texnomart'], dtype='<U9') # ↑ truncated to 9 — silently, no error

a[0] = "Texnomart Plaza"

Texnomart✂·Plaza

The cell holds exactly 9 characters. The rest is dropped without an error — data is lost silently.

S in action

S: one byte per character — and a crash on Cyrillic

>>> b = np.array(["Tashkent", "Evos"], dtype="S") >>> b array([b'Tashkent', b'Evos'], dtype='|S8') # 1 byte/char >>> np.array(["Ташкент"], dtype="S") UnicodeEncodeError: 'ascii' codec can't encode characters in position 0-6
"Tashkent"→b'Tashkent'✓

Latin: each character is 1 ASCII byte

"Ташкент"→✗ UnicodeEncodeError

Cyrillic does not fit into ASCII

object in action

object: 8 bytes of pointer instead of a string

>>> o = np.array(["Ташкент", "Самарканд"], dtype=object) >>> o.dtype dtype('O') >>> o.itemsize 8 # 8 bytes = a pointer, not a string

object array: pointers in a row

0x··a10x··c80x··04
↓↓↓

strings scattered across the heap

"Самарканд" "Ташкент" "Бухара"

The array of pointers is tiny (50,000 regions — just 0.4 MB), but the strings themselves live as separate Python objects. The processor chases each one: a cache miss on every element, and vectorization does not work.

NumPy

Text types: U and S

In NumPy text is a fixed-width type: the width equals the longest string, and a value that is too long is silently truncated.

S - bytes

1 byte per character

  • Latin only (ASCII)
  • Fails with an error on Cyrillic
  • Saves memory
U - Unicode

4 bytes per character

  • Any language, including Russian
  • Takes more memory
  • The default choice for text

Under the hood

object: an array of pointers, not values

The object type stores not the strings themselves but 64-bit addresses: pointers to places in RAM where the strings actually reside. The strings themselves are scattered across memory at random.

object - pointers

Cache miss on every element

  • CPU reads the address
  • Jumps to another part of memory
  • Reads the string
  • Returns for the next address
int64 - values

Processor steps through the block

  • All values lie next to each other
  • Next = +8 bytes
  • CPU cache is not flushed
  • Vectorization works

In pandas 3.0 a pure text column gets the str type by default, not object - this is the first step toward bringing speed back to text.

pandas smart types

Extension types: missing values and savings

pandas added extension types on top of NumPy. They store missing values right in the column and save memory.

string

A dedicated type for text columns. Supports NA. Does not allow mixing with numbers or lists.

Int64, boolean

Integers and boolean with NA support. The capital letter distinguishes them from their NumPy counterparts.

category

Unique values are stored once. The column holds numeric codes. Saves memory by 10-100 times.

datetime (TZ)

A moment in time with a time zone.

Period

A calendar span: quarter, month.

Interval

A numeric range, for example (0, 10].

Missing values in integers

Int64: integer with a missing value

A regular NumPy integer does not store NaN, so a single missing value turns the column into fractions and corrupts numeric ids.

regular int + NaN

Turns into float

  • 101 becomes 101.0
  • numeric id is corrupted
Int64

Stays an integer

  • 101 stays 101
  • a missing value is <NA>

Memory

category: numeric codes instead of strings

When a column has few distinct values repeated many times (cities, statuses), the category type stores each string once in a dictionary and keeps small codes in the column. On a column with thousands of repeats this cuts memory by tens of times.

Measure a column's memory: memory_usage(deep=True). The deep parameter is required for text, otherwise only the size of the references is counted.

Question

The status column has type string. df[df["status"].str.contains("success")] raises an error. The same code worked when the type was object. Why?

str.contains() ran without error and returned a result. The error occurred when using that result as a mask for indexing.

Answer

string returns NA instead of False on empty cells - a mask with NA cannot be used

With type object an empty cell gives False in str.contains(). With type string - NA. pandas cannot use a mask containing NA for indexing. Solution: df["status"].str.contains("success", na=False) - the na=False parameter replaces NA with False.

Cleaning

Cleaning takes 60-70% of a project's time

Real data comes in dirty: missing values, numbers as text, duplicates, mixed case in categories. Cleaning comes before analysis, because bad data on the input gives wrong conclusions on the output.

Analysis on unclean data produces wrong results. Cleaning comes before any calculations.

Selection

Labels and positions: loc and iloc

Rows and columns have both numbers (positions) and names (labels). pandas gives two ways to access them.

iloc

By positions

  • Row and column numbers from zero
  • Like array indexing in Lecture 11
  • The upper bound of a slice is excluded
loc

By labels

  • Row names (index) and column names
  • You can select rows with a mask
  • The upper bound of a slice is included

Filtering

A boolean mask selects rows by a condition

Comparing a column with a number gives an array of True/False for each row. Inside square brackets it keeps only the rows where True. This is a continuation of the boolean masks from Lecture 11.

Several conditions are combined with & (AND) and | (OR), each in parentheses. The words and and or do not work here.

Audience question

You wrote filtered = df[df.amount > 1e6], then filtered["fee"] = 0. Did the original df change?

Intuitively it seems yes, filtered is the same table. But Python shows a SettingWithCopyWarning.

Answer

df did not change: filtering returned a copy

Filtering may return a copy or a view - unpredictably. The write goes into the copy, the original does not change. The right way: df.loc[df.amount > 1e6, "fee"] = 0 - one loc call guarantees the write into the original.

Missing values

NaN: a missing value

In real data some of the values are missing and marked as NaN. NaN is not equal to anything, not even to itself, so you cannot catch it with the == comparison. Aggregates like mean skip NaN automatically.

Missing values are found with isna, removed with dropna or filled with fillna. What to choose depends on whether you can afford to lose the row.
