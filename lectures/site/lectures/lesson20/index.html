Команда

GROUP BY · Агрегации

COUNT · SUM · AVG · MIN · MAX · HAVING

Агрегации

COUNT · AVG · MIN · MAX - по всей таблице

Команда
SELECT COUNT(*) AS vsego, COUNT(DISTINCT user_id) AS unikal_users, ROUND(AVG(days_since_prior_order), 1) AS srednee_dney, MIN(days_since_prior_order) AS min_dney, MAX(days_since_prior_order) AS max_dney FROM public.orders WHERE days_since_prior_order IS NOT NULL;

Без GROUP BY - одна строка по всей таблице. IS NOT NULL нужен - иначе AVG считается с пропуском NULL строк, а COUNT(*) будет расходиться.

Агрегации

GROUP BY - одна строка на группу

Команда

Агрегации

HAVING - фильтр после GROUP BY

Команда
SELECT user_id, COUNT(*) AS orders_count, ROUND(AVG(days_since_prior_order), 1) AS avg_days FROM public.orders WHERE days_since_prior_order IS NOT NULL GROUP BY user_id HAVING COUNT(*) >= 50 ORDER BY orders_count DESC LIMIT 5;

WHERE фильтрует строки ДО группировки. HAVING фильтрует группы ПОСЛЕ - поэтому в HAVING можно писать COUNT(*) и другие агрегации.

INNER JOIN - только совпадающие строки

Команда

p, a, d - псевдонимы таблиц. Потом пишем p.product_name вместо длинного products.product_name. Обязательно когда в двух таблицах одинаковые имена колонок.

LEFT JOIN - все строки левой, NULL если нет совпадения

Модуль 5

CTE (WITH)

Именованный подзапрос - сложное делаем читаемым

WITH - даём подзапросу имя

Команда
WITH user_stats AS ( SELECT user_id, COUNT(*) AS orders_count, ROUND(AVG(days_since_prior_order), 1) AS avg_days FROM public.orders WHERE days_since_prior_order IS NOT NULL GROUP BY user_id ) SELECT * FROM user_stats WHERE orders_count >= 30 ORDER BY orders_count DESC LIMIT 5;

CTE = подзапрос с именем. Используется как обычная таблица после AS. Можно ссылаться несколько раз. Несколько CTE разделяются запятой.

Window Functions

ROW_NUMBER - топ-N внутри группы

Команда
WITH ranked AS ( SELECT p.product_name, d.department, COUNT(*) AS cnt, ROW_NUMBER() OVER ( PARTITION BY d.department ORDER BY COUNT(*) DESC ) AS rn FROM public.order_products_prior op JOIN public.products p ON op.product_id = p.product_id JOIN public.departments d ON p.department_id = d.department_id GROUP BY p.product_name, d.department ) SELECT department, product_name, cnt, rn FROM ranked WHERE rn <= 2 ORDER BY department, rn;

Window Functions

LAG - значение из предыдущей строки

Команда
WITH hourly AS ( SELECT order_hour_of_day AS hour, COUNT(*) AS orders FROM public.orders GROUP BY order_hour_of_day ) SELECT hour, orders, LAG(orders) OVER (ORDER BY hour) AS prev_hour, orders - LAG(orders) OVER (ORDER BY hour) AS delta FROM hourly ORDER BY hour;

LAG(x) - значение x из предыдущей строки. LEAD(x) - из следующей. Первая строка не имеет предыдущей → NULL.

Модуль 7

CASE WHEN

Условная логика прямо в запросе

CASE WHEN

Создаём категорию из числа

Команда
SELECT order_id, order_hour_of_day, CASE WHEN order_hour_of_day < 6 THEN 'Ночь' WHEN order_hour_of_day < 12 THEN 'Утро' WHEN order_hour_of_day < 18 THEN 'День' ELSE 'Вечер' END AS period FROM public.orders LIMIT 5;

CASE проверяет условия сверху вниз и берёт первое совпадение. ELSE - если ни одно не сработало. Работает в SELECT, GROUP BY, ORDER BY, HAVING.

CASE + GROUP BY - RFM сегментация

Команда
WITH stats AS ( SELECT user_id, COUNT(*) AS freq, ROUND(AVG(days_since_prior_order), 1) AS recency FROM public.orders WHERE days_since_prior_order IS NOT NULL GROUP BY user_id ) SELECT CASE WHEN freq >= 20 AND recency <= 10 THEN 'Champions' WHEN freq >= 10 AND recency <= 20 THEN 'Loyal' WHEN recency > 25 THEN 'At Risk' ELSE 'New' END AS segment, COUNT(*) AS users FROM stats GROUP BY 1 ORDER BY users DESC;

Модуль 8

Своя схема

CREATE TABLE · DROP · INDEX · EXPLAIN

Своя схема

CREATE TABLE AS SELECT - сохрани результат

Команда
CREATE TABLE my_rfm AS SELECT user_id, COUNT(*) AS total_orders, ROUND(AVG(days_since_prior_order), 1) AS avg_days, CASE WHEN COUNT(*) >= 20 THEN 'VIP' WHEN COUNT(*) >= 10 THEN 'Regular' ELSE 'New' END AS segment FROM public.orders WHERE days_since_prior_order IS NOT NULL GROUP BY user_id; -- Смотрим что получилось SELECT segment, COUNT(*) AS users FROM my_rfm GROUP BY segment;
Результат - таблица создана в твоей схеме
segmentusers
VIP31,890
Regular58,442
New115,877
таблица только в твоей схеме · другие не видят

public - только SELECT. Твоя схема - CREATE / INSERT / UPDATE / DELETE / DROP. Удалить: DROP TABLE IF EXISTS my_rfm;

Производительность

EXPLAIN ANALYZE + CREATE INDEX

Команда
-- 1. Смотрим план запроса EXPLAIN ANALYZE SELECT * FROM my_rfm WHERE segment = 'VIP'; -- 2. Создаём индекс CREATE INDEX idx_rfm_seg ON my_rfm(segment); -- 3. Снова смотрим план EXPLAIN ANALYZE SELECT * FROM my_rfm WHERE segment = 'VIP';

Seq Scan - читает каждую строку подряд (медленно). Index Scan - прыгает сразу к нужным строкам (быстро). На больших таблицах разница в 10–100x.

До индекса - Seq Scan
Query Plan
Seq Scan on my_rfm
Filter: (segment = 'VIP')
actual time = 38.4 ms
После индекса - Index Scan
Query Plan
Index Scan using idx_rfm_seg
Index Cond: (segment = 'VIP')
actual time = 4.2 ms
