Kontekst

Exception asoslari

Exception ierarxiyasi: bu ham OOP

try/except chuqurroq

else bloki: faqat muvaffaqiyatda bajariladi

Aniq ajratish: "xavfli amal", "xatoni qayta ishlash" va "muvaffaqiyatda kod" turli bloklarda yotadi.

try: xavfli_amal() # exception tashlashi mumkin except SomeError: xatoni_qayta_ishlash() # faqat exception bo'lganda else: muvaffaqiyatda() # faqat exception bo'lmaganda finally: doim() # har qanday holatda bajariladi

Agar "muvaffaqiyatda kod"'ni try ichiga qo'ysangiz, uning xatolarini ham except ushlaydi va xavfli amal xatolari kabi qayta ishlaydi. Bu loglarda chalkashlik.

try/except chuqurroq

else amaliyotda: COMMIT faqat muvaffaqiyatda

Kontekst menejerlari

Muammo: resurs yopilmadi

Har bir resurs (fayl, ulanish, lok) ishdan keyin yopilishi kerak. Agar ochish va yopish o'rtasida exception sodir bo'lsa, f.close() qatori shunchaki bajarilmaydi.

f = open("payments.txt", "r") data = f.read() int("abc") # bu yerda ValueError yiqildi f.close() # bu qator bajarilmaydi

Bu resurs sizib chiqishi: fayl band, xotira ozod qilinmagan. Minglab so'rovlar bo'lgan serverda bunday sizib chiqishlar to'planib jarayonni yiqitadi.

Kontekst menejerlari

with nima

with Python'ga shunday deydi: "buni och, menga ishlashga ruxsat ber, xato bo'lsa ham buni o'zing yop". try/finally'dan qisqaroq va ishonchliroq.

try/finally orqali
f = open("payments.txt", "r") try: data = f.read() finally: f.close()
with orqali
with open("payments.txt", "r") as f: data = f.read() # close() avtomatik chaqiriladi

__enter__ va __exit__ metodlariga ega class with bilan ishlaydi. __exit__ doim, hatto blok ichida exception bo'lganda ham chaqiriladi. Resursni ozod qilish kafolati shundadir.

Kontekst menejerlari

with ichida qanday ishlaydi

with'ga uzatilgan obyekt ikkita metodga ega bo'lishi shart: __enter__ (blokka kirish) va __exit__ (chiqish). Python ularni siz uchun chaqiradi.

with open("payments.txt") as f: | +-- 1. __enter__() faylni ochadi, f'ni qaytaradi | +-- 2. with blokining tanasi bajariladi | | | +-- hammasi OK __exit__() chaqiriladi, fayl yopiladi | +-- exception bo'ldi __exit__() chaqiriladi, fayl yopiladi, | keyin exception keyingisiga uchadi | +-- 3. resurs kafolatli ozod qilingan

with'ning asosiy qiymati: __exit__() doim chaqiriladi. Hatto blok ichida exception bo'lganda ham resurs ozod qilinadi.

MB bilan ishlaganda with bir vaqtda ikkita ishni qiladi: tranzaksiyani boshqaradi (muvaffaqiyatda commit, xatoda rollback) va oxirida ulanishni yopadi.

import psycopg2 def transfer(from_id: str, to_id: str, amount: float) -> None: with psycopg2.connect(database="payments") as conn: with conn.cursor() as cur: cur.execute( "UPDATE accounts SET balance = balance - %s WHERE id = %s", (amount, from_id), ) cur.execute( "UPDATE accounts SET balance = balance + %s WHERE id = %s", (amount, to_id), ) # with'dan chiqishda: # muvaffaqiyat -> conn.commit(), cur.close(), conn.close() # xato -> conn.rollback(), cur.close(), conn.close()

Celery fon vazifasida xuddi shunday konstruksiya MBda osilib qolgan tranzaksiyalar va worker vazifalari orasida yopilmagan ulanishlar qolmasligini kafolatlaydi.

Kontekst menejerlari

with va try/except birgalikda

with resurslar uchun, try/except xatolar uchun javobgar. Ko'pincha ular birga ishlatiladi.

try: with open("payments.txt", "r") as f: data = f.read() process(data) except FileNotFoundError as e: print(f"Fayl topilmadi: {e}") except ValueError as e: print(f"Qayta ishlash xatosi: {e}") # Fayl har qanday holatda yopilgan. # Exception ushlangan va qayta ishlangan.

Fayl avtomatik yopiladi, hatto exception tashqi try/except bloki tomonidan ushlanganda ham.

Kontekst menejerlari

DBTransaction: avtomatik COMMIT yoki ROLLBACK

class DBTransaction: def __init__(self, session_id: str): self.session_id = session_id def __enter__(self) -> "DBTransaction": print(f"[BEGIN] Sessiya {self.session_id}") return self def __exit__(self, exc_type, exc_val, exc_tb) -> bool: if exc_type is None: print(f"[COMMIT] Sessiya {self.session_id}, ma'lumotlar saqlandi") else: print(f"[ROLLBACK] {exc_type.__name__}: {exc_val}") return False # exception'ni tashqariga uzatamiz def execute(self, query: str) -> None: print(f" [SQL] {query}") # Muvaffaqiyat: avtomatik COMMIT with DBTransaction("SES_001") as tx: tx.execute("UPDATE accounts SET balance = balance - 350000 WHERE id = 'A'") tx.execute("UPDATE accounts SET balance = balance + 350000 WHERE id = 'B'") # Xato: avtomatik ROLLBACK try: with DBTransaction("SES_002") as tx: tx.execute("UPDATE accounts SET balance = balance - 999999 WHERE id = 'A'") raise ValueError("CHECK constraint: balance < 0") except ValueError as e: print(f"[API] {e}")

Kontekst menejerlari

@contextmanager: generator orqali menejer

Doim butun class kerak emas. Oddiy holatlar uchun contextlib'dan @contextmanager dekoratori bor: yield'gacha bo'lgan kod bu __enter__, yield'dan keyin bu __exit__.

from contextlib import contextmanager import time @contextmanager def measure_time(operation: str): """Bajarish vaqtini o'lchaydi""" start = time.perf_counter() print(f"[TIMER] Start: {operation}") try: yield # bu yerda with ichidagi kod bajariladi finally: ms = (time.perf_counter() - start) * 1000 print(f"[TIMER] {operation}: {ms:.1f}ms") @contextmanager def redis_lock(resource_id: str): """Taqsimlangan lok imitatsiyasi""" key = f"lock:{resource_id}" print(f"[REDIS] {key} olinmoqda") try: yield key finally: print(f"[REDIS] {key} ozod qilinmoqda") with measure_time("payment"): with redis_lock("account:UZ_5521") as lock: print(f" Ishlayapmiz (lock={lock})") time.sleep(0.03)

Chiqish tartibi kirish tartibiga teskari. Ichki lok birinchi bo'lib olib tashlanadi.

logging moduli

Logging nima

Logging: dastur ishlashi davomida hodisalarini yozish. Nima sodir bo'ldi, qachon, qaysi serverda, qaysi funksiyada.

Analogiya: samolyotning qora qutisi. Har qanday insidentdan keyin muhandis yozuvni ochib, sbo'ydan oldin tizimda nima sodir bo'lganini ko'radi.

  • Productionda debugger yo'q. Faqat loglarga tushgan narsa mavjud.
  • Mikroservislarda tranzaksiya bir nechta servis orqali o'tadi: loglarsiz qayerda osilib qolganini topib bo'lmaydi.
  • Audit. Bank kim va nima qilganini saqlashga majbur.

Yakuniy masala

Yechim: validator

Toifalar bo'yicha uchta xato class'i. Bitta validator: yo OK, yo kerakli turdagi raise.

import logging logger = logging.getLogger("swift") MAX = 10_000_000 SANCTIONED = {"SANCTION"} class StructureError(Exception): pass # buzilgan ma'lumotlar class BusinessError(Exception): pass # biznes qoidalari class ComplianceError(Exception): pass # sanksiyalar def process_payment(p): if not isinstance(p, dict): raise StructureError(f"Lug'at emas: {type(p).__name__}") for field in ("from", "to", "amount"): if field not in p: raise StructureError(f"Maydon yo'q: {field}") try: amount = float(p["amount"]) except ValueError: raise StructureError(f"Summa raqam emas: {p['amount']}") if p["from"] == p["to"]: raise BusinessError(f"Bir xil hisob: {p['from']}") if amount > MAX: raise BusinessError(f"Limit: {amount}") if p["to"] in SANCTIONED: raise ComplianceError(f"Sanksiyalar: {p['to']}")

Yechim: paketli qayta ishlash
