Часть 1

Три инструмента

Подзапрос, CTE и оконные функции. Сначала разбираем каждый, потом применяем на задачах.

Обзор

Что разберём сегодня

1

Подзапрос

Запрос внутри запроса. Даёт значение или список для условия. Пример: оборот выше среднего.

2

CTE (WITH)

Именованный шаг. Сложный запрос разбивается на читаемые блоки сверху вниз.

3

Оконные функции

Расчёт по группе строк без их схлопывания: рейтинг, нарастающий итог, соседняя строка.

Инструмент 1

Подзапрос: запрос внутри запроса

Как работает

Внутренний запрос (в скобках) выполняется первым. Его результат подставляется во внешний запрос как готовое значение.

Одно значение

Скаляр в WHERE или SELECT. Пример: сравнение со средним.

Список

Колонка значений с IN (...).

Таблица

Производная таблица в FROM.

Пример: клиенты выше среднего
SELECT full_name, total FROM cust_total WHERE total > (SELECT AVG(total) FROM cust_total)

Зелёное = подзапрос. Он возвращает одно число (среднее), считается один раз и сравнивается с каждой строкой.

Инструмент 2

CTE: имя для шага запроса

Как работает

WITH имя AS ( ... ) даёт подзапросу имя. Дальше к нему обращаются как к обычной таблице.

Читаемость

Шаги идут сверху вниз, а не вложены друг в друга.

Несколько шагов

Несколько CTE через запятую: посчитать, отранжировать, отфильтровать.

Повтор

Один результат можно использовать дальше дважды по имени.

Пример: тот же расчёт оборота, вынесенный в CTE
WITH cust_total AS ( SELECT customer_id, SUM(amount) AS total FROM ... GROUP BY customer_id ) SELECT * FROM cust_total WHERE total > 20000000

Зелёное = CTE. Шаг получил имя cust_total и используется ниже как таблица.

Инструмент 3

Оконные функции

Что такое окно и почему строки не пропадают.

Оконные функции · идея

GROUP BY и OVER

GROUP BY: одна строка на группу
SELECT category, SUM(amount) AS total FROM purchases GROUP BY category
categorytotal
Еда600
Техника900
5 строк → 2 строки. Детали пропали.
OVER: все строки на месте
SELECT txn, category, amount, SUM(amount) OVER (PARTITION BY category) AS by_cat FROM purchases
txncategoryamountby_cat
1Еда100600
2Еда300600
3Еда200600
4Техника500900
5Техника400900
5 строк остались, итог группы рядом

GROUP BY - строка на группу. OVER (...) приписывает итог группы к каждой строке, строки остаются.

Оконные функции · анатомия

Из чего состоит OVER

SUM(amount) OVER ( PARTITION BY category ORDER BY txn )
обязателен

OVER ( … )

Само слово OVER делает функцию оконной. Без него это обычный агрегат.

необязателен

PARTITION BY

Делит строки на группы и считает внутри каждой. Без PARTITION BY окно - это вся таблица.

по ситуации

ORDER BY

Задаёт порядок в окне. Нужен для рангов, LAG и нарастающего итога.

OVER делает функцию оконной, PARTITION BY задаёт группы, ORDER BY задаёт порядок.

Внутри OVER · вариант 1

OVER (): окно - это вся таблица

Пример
SELECT txn, amount, SUM(amount) OVER () AS total FROM purchases

Окно = все строки, поэтому total одинаков в каждой строке (1 500). Деля amount / total, получаем долю строки от общего.

Подвигай: указатель идёт по строкам
txncategoryamountрезультат
Нажми «Шаг» или «Играть».

Внутри OVER · вариант 2

PARTITION BY: окно - это своя группа

Пример
SELECT txn, category, amount, SUM(amount) OVER (PARTITION BY category) AS by_cat FROM purchases

Окно = строки той же категории, что и текущая. У «Еда» итог 600, у «Техника» 900. Строки остаются, итог группы рядом.

Подвигай: окно сужается до категории
txncategoryamountрезультат
Нажми «Шаг» или «Играть».

Внутри OVER · вариант 3

ORDER BY: окно растёт по порядку

Пример
SELECT txn, amount, SUM(amount) OVER (ORDER BY txn) AS running FROM purchases

Окно = от первой строки до текущей. Поэтому running накапливается: 100, 400, 600, 1 100, 1 500.

Подвигай: окно растёт до текущей строки
txncategoryamountрезультат
Нажми «Шаг» или «Играть».

Оконные функции · приёмы

Популярные приёмы

Топ-N в группе · ROW_NUMBER

Лучшие внутри каждой группы.

ROW_NUMBER() OVER (PARTITION BY cat ORDER BY amount DESC)

Рейтинг · RANK / DENSE_RANK

Место по значению, с учётом ничьих.

RANK() OVER (ORDER BY turnover DESC)

Нарастающий итог · SUM OVER

Накопление по времени.

SUM(amount) OVER (ORDER BY txn_ts)

Прошлый / следующий · LAG / LEAD

Сравнение с соседним периодом.

LAG(total) OVER (ORDER BY mon)

Доля от общего · SUM OVER ()

Процент строки или группы.

amount / SUM(amount) OVER ()

Корзины · NTILE(n)

Разбить на n равных групп (RFM).

NTILE(4) OVER (ORDER BY spent DESC)

Оконные функции · пример

Топ-3 мерчанта в каждой категории

ROW_NUMBER внутри категории, затем rn <= 3
SELECT category, name, turnover FROM ( SELECT m.category, m.name, SUM(t.amount) AS turnover, ROW_NUMBER() OVER (PARTITION BY m.category ORDER BY SUM(t.amount) DESC) AS rn FROM transactions t JOIN merchants m ON m.merchant_id = t.merchant_id WHERE t.status = 'success' GROUP BY m.category, m.name ) x WHERE rn <= 3;

Часть 2

Как подойти к задаче

Сначала выбрать инструмент, затем разбить задачу на шаги.

Выбор инструмента

Какой инструмент для какого вопроса

JOIN

Нужны колонки из другой таблицы

Таблицы соединяются по ключу. Пример: показать имя клиента рядом с платежом.

Подзапрос

Нужно значение внутри условия

Сначала считается одно значение, затем с ним идёт сравнение. Пример: оборот выше среднего.

CTE (WITH)

Запрос из нескольких шагов

Каждому шагу даётся имя. Шаги читаются сверху вниз. Пример: посчитать, отранжировать, отфильтровать.

Окно

Расчёт по группе без потери строк

Примеры: номер внутри группы, нарастающий итог, значение из соседней строки.

GROUP BY оставляет одну строку на группу. Оконная функция считает по группе, но сохраняет все строки. Поэтому «топ-N внутри группы» делается оконной функцией.

Метод

Разбиение задачи на шаги

Задача

Клиенты, у которых оборот в мае ниже апрельского более чем на 30%.

Нужны три шага: оборот по месяцам, сравнение с прошлым месяцем и фильтр. В один SELECT они не умещаются.

Метод

Три шага и один запрос

Три шага

Шаг 1. оборот по клиенту за каждый месяц

Шаг 2. рядом оборот предыдущего месяца (LAG)

Шаг 3. оставить май, где май < апрель × 0.7

Один запрос из трёх частей
WITH monthly AS ( -- шаг 1 ... ),mom AS ( -- шаг 2: LAG ... )SELECT ... -- шаг 3: фильтр FROM mom WHERE may < apr * 0.7;

Каждый шаг - это отдельный CTE, его пишут и проверяют по одному.

Клиенты выше среднего

Шаг 1. Оборот по каждому клиенту

Разбор 2 · CTE и подзапрос, шаг 2

Сравнение со средним

Шаг 2. Фильтр по среднему
SELECT full_name, total FROM cust_total WHERE total > ( SELECT AVG(total) -- подзапрос FROM cust_total ) ORDER BY total DESC;

Разбор 3 · Конвейер из CTE

Снижение оборота в мае

Та же задача, три шага в одном запросе
WITH monthly AS ( -- шаг 1: оборот по месяцам SELECT ca.customer_id, date_trunc('month', t.txn_ts) AS mon, SUM(t.amount) AS total FROM transactions t JOIN cards ca ON t.card_id = ca.card_id WHERE t.status = 'success' GROUP BY ca.customer_id, mon ),mom AS ( -- шаг 2: предыдущий месяц SELECT *, LAG(total) OVER ( PARTITION BY customer_id ORDER BY mon ) AS prev FROM monthly )SELECT c.full_name, mom.prev AS apr, mom.total AS may, ROUND((mom.total - mom.prev) * 100.0 / mom.prev) AS pct -- шаг 3: фильтр FROM mom JOIN customers c ON c.customer_id = mom.customer_id WHERE mom.mon = DATE '2025-05-01' AND mom.prev > 0 AND mom.total < mom.prev * 0.7 ORDER BY pct;
