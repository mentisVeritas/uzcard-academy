Задача 1 · Сводная таблица

Оборот по категориям и месяцам

Вопрос от маркетинга: таблица, где строки это категории, колонки это месяцы, в клетках оборот.

Обычный GROUP BY category, month даёт длинный список. Нужно, чтобы месяцы стали колонками. Это сводная таблица (pivot).

Приём: CASE внутри SUM. Каждая колонка это отдельный SUM(CASE WHEN месяц = N ...), по одной колонке на месяц.

Задача 1 · Решение

SUM(CASE ...) на каждый месяц

Запрос
SELECT m.category, SUM(CASE WHEN EXTRACT(MONTH FROM t.txn_ts)=2 THEN t.amount ELSE 0 END) AS feb, SUM(CASE WHEN EXTRACT(MONTH FROM t.txn_ts)=3 THEN t.amount ELSE 0 END) AS mar, SUM(CASE WHEN EXTRACT(MONTH FROM t.txn_ts)=4 THEN t.amount ELSE 0 END) AS apr, SUM(CASE WHEN EXTRACT(MONTH FROM t.txn_ts)=5 THEN t.amount ELSE 0 END) AS may FROM transactions t JOIN merchants m ON t.merchant_id = m.merchant_id WHERE t.status = 'success' GROUP BY m.category ORDER BY feb+mar+apr+may DESC;

Задача 2 · Скользящее среднее

Сгладить дневной оборот

Вопрос: дневной оборот скачет вверх-вниз, тренд не виден. Нужна сглаженная линия.

Скользящее среднее это среднее за последние 7 дней в каждой точке. Дневной шум усредняется, тренд проявляется.

Новое в оконных функциях: рамка окна ROWS BETWEEN 6 PRECEDING AND CURRENT ROW это текущая строка и 6 предыдущих, то есть 7 дней.

Задача 2 · Решение

AVG OVER с рамкой из 7 дней

Запрос
WITH daily AS ( SELECT t.txn_ts::date AS day, SUM(t.amount) AS revenue FROM transactions t WHERE t.status = 'success' GROUP BY day ) SELECT day, revenue, ROUND(AVG(revenue) OVER ( ORDER BY day ROWS BETWEEN 6 PRECEDING AND CURRENT ROW )) AS ma7 FROM daily ORDER BY day;

Сначала CTE сворачивает транзакции в дневной оборот. Затем окно считает среднее по скользящему интервалу из 7 строк.

Задача 3 · Воронка

Где теряются заказы

Вопрос (данные olist, интернет-магазин): заказ проходит этапы оформлен, подтверждён, отправлен, доставлен. На каком шаге теряется больше всего.

Воронка это счётчик заказов, дошедших до каждого этапа, и процент отвала между этапами.

Приём: у каждого этапа своя дата (order_approved_at, ..._delivered_customer_date). Если даты нет, этап не пройден. COUNT(колонка) считает только непустые.

Задача 3 · Решение

COUNT по колонке этапа

Запрос
SELECT COUNT(*) AS purchased, COUNT(order_approved_at) AS approved, COUNT(order_delivered_carrier_date) AS shipped, COUNT(order_delivered_customer_date) AS delivered FROM olist_orders;

COUNT(*) считает все строки, COUNT(колонка) только те, где колонка не NULL. Разница между этапами это потери.

Результат как воронка
этапзаказов%отвал
Оформлен99 441100.0%старт
Подтверждён99 28199.8%-0.2%
Отправлен97 65898.2%-1.6%
Доставлен96 47697.0%-1.2%
до клиента доходит 97% заказов

Больше всего теряется на шаге отправки (отвал 1.6%). Вывод: смотреть логистику между подтверждением и отгрузкой.
