ndarray

ndarray: тип для хранения числовых данных

Строку хранит str, одно число - int. Но набор чисел - вы храните в list. NumPy заменяет именно список, когда данные числовые: он хранит их эффективнее и работает с ними быстрее.

Python list: [1, 2, 3.0, 'два']

Гибкий, но медленный

  • Каждый элемент - отдельный Python-объект в памяти
  • Элементы разбросаны по разным адресам
  • Можно хранить разные типы: int, str, float вместе
  • Любая операция требует Python-цикла
NumPy ndarray: np.array([1, 2, 3, 4])

Строгий, но быстрый

  • Все элементы - один тип: float64, int32...
  • Один непрерывный блок памяти
  • CPU читает данные подряд - без прыжков по памяти
  • Операции без цикла: a + b, a * 2, np.sum(a)

ndarray = N-dimensional array. 1D - вектор, 2D - матрица, 3D - куб (например, RGB-изображение). Один тип данных на весь массив.

Вопрос аудитории

Зачем NumPy требует, чтобы все элементы были одного типа?

Python-список может содержать [1, 'два', 3.0, True]. NumPy отказывается. Почему это ограничение - на самом деле преимущество?

Ответ

Одинаковый тип = предсказуемый размер = быстрая математика

Если каждый элемент занимает ровно 8 байт (int64), CPU знает заранее, где находится любой элемент: адрес = начало + индекс * 8.

NumPy использует SIMD-инструкции процессора: за один такт складывается 4-8 чисел. Python-список работает с одним числом за раз.

Под капотом

np.sum(): один вызов C-функции вместо миллиона шагов интерпретатора

Математика одна и та же. Разница в том, что происходит вокруг каждого сложения.

for x in data: total += x

На каждой из 1 000 000 итераций:

  • Интерпретатор читает байткод
  • Ищет переменную x по имени в памяти
  • Проверяет тип объекта
  • Достаёт число из Python-объекта
  • Делает сложение
  • Создаёт новый Python-объект с результатом
np.sum(a)

Один вызов C-функции:

  • Получает указатель на начало блока памяти
  • CPU берёт SIMD-инструкцию (AVX2)
  • За один такт складывает 4-8 чисел одновременно
  • Нет Python-объектов, нет проверок типов
  • Нет создания промежуточных объектов

Аналогия: считать 1000 монет по одной vs высыпать в машину-счётчик. Операция та же - считать. Но машина обрабатывает несколько монет одновременно и не спрашивает каждый раз "это точно монета?"

Фильтрация

Boolean-маска: выборка по условию

Создаём массив True/False и используем его как маску. NumPy вернёт только элементы, где True.

scores = np.array([85, 42, 91, 38, 76, 55, 99, 20]) mask = scores > 60 # [True, False, True, False, True, False, True, False] passing = scores[mask] # array([85, 91, 76, 99]) # Одной строкой: passing = scores[scores > 60]

Условие scores > 60 не возвращает True/False - оно возвращает массив булевых значений. Этот массив используется как фильтр.

Найти крупные транзакции за день

10 000 транзакций. Найти все суммы выше 1 000 000 сум - мониторинг крупных платежей.

Обнаружение аномалий

Z-score - насколько далеко от нормы

Z-score показывает, на сколько стандартных отклонений элемент отличается от среднего.

z = (x - μ) / σ
x - значение
μ - среднее
σ - std
|z| < 2
норма
2 ≤ |z| < 3
внимание
|z| ≥ 3
аномалия

В нормальном распределении: 68% в ±1σ, 95% в ±2σ, 99.7% в ±3σ. Транзакция с z > 3 - один случай из 370.

Нормальное распределение

Три зоны: норма - внимание - аномалия

Выброс с z > 3 встречается реже чем в 0.3% случаев.

Волатильность портфеля за 90 дней - 5 строк

Стандартное отклонение дневных доходностей, умноженное на sqrt(252), даёт годовую волатильность. Это стандартная формула в финансовом анализе.

Симуляция

Оценить Pi за 3 строки - метод Монте-Карло

Бросаем 1 000 000 случайных точек в квадрат. Считаем попавшие в единичный круг. Доля × 4 = Pi.

np.random.seed(0) N = 1_000_000 # Случайные точки в квадрате [-1,1] x [-1,1] x = np.random.uniform(-1, 1, N) y = np.random.uniform(-1, 1, N) # Попала ли точка в единичный круг? inside = (x**2 + y**2) <= 1.0 pi_estimate = 4.0 * inside.sum() / N print(f"Оценка Pi: {pi_estimate:.5f}") print(f"Настоящий Pi: {np.pi:.5f}") print(f"Ошибка: {abs(pi_estimate - np.pi):.5f}")
Оценка Pi: 3.14136 Настоящий Pi: 3.14159 Ошибка: 0.00023

Это не игрушка - финансовые компании используют Монте-Карло для оценки рисков портфеля. NumPy делает 1 000 000 операций за миллисекунды.
